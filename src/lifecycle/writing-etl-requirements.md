# Writing ETL Requirements

Read every `.md` file below the BA-owned `input/` folder and build an evidence ledger with stable `SRC-NNN` identifiers and exact file/section locators. Map evidence across objective and scope, source contract, target contract, mapping rules, load behavior, controls and security, acceptance criteria, decisions, open questions, and evidence.

Silence means missing, not not-applicable. Separate repository-discoverable facts from business decisions. Search configured project roots for the former; ask the user only for the latter. Conflicting sources remain visible until an authority resolves them.

Write `<REQ>/requirement.md`. Active `R-NNN` and `AC-NNN` rows must cite supported evidence or an attributed decision. IDs are append-only; supersede rather than delete or renumber. Keep observable WHAT separate from Pentaho HOW. No secrets, invented defaults, or unsupported assumptions.

The artifact is ready for design when required sections and ID references validate, placeholders are gone, and no blocking business question remains. Readiness is a technical self-assessment; no human approval fields or gate are required.
